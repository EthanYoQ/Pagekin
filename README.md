<h1 align="center">书童 Pagekin</h1>

<p align="center"><sub>原名「AI 小说作家 / AI Novel Writer」</sub></p>

<p align="center">
  <strong>书童（Pagekin）是一款免费开源的 AI 写小说桌面软件，适用于 Windows 和 macOS，给想用 AI 写长篇小说的作者用。</strong><br />
  从设定、架构、角色、章节蓝图到正文的写作、审稿、修稿、定稿，一章一章把书写完。也能拆解参考小说来仿写、导入自己的原稿接着续写，或按你的意见改写。<br />
  本地优先：作品存在你自己的电脑上。软件不带模型：接你自己的 API Key（DeepSeek、OpenAI、Gemini、智谱等），或用 Ollama 跑本地模型。
</p>

## 它能做什么

书童按写一本小说的顺序工作：你是作者，它是书童。每一步的结果都存进作品，下一步接着用。AI 负责起草，每一步由你确认。

### 书房：管理你的全部作品

书房列出你写过的每一部作品。点封面可以先看概览：写到第几步、正文字数、定稿章数、角色数。可以新建作品，也可以把旧版本的项目导入成一份副本。

![书房：书架上有两部作品，右侧是《灯塔》的概览和进度](docs/assets/readme/v130-zh-library.webp)

### 拆解、仿写、续写与改写

书房里的「小说拆解与仿写」可以导入一部 .txt、.md 或 .epub 小说，按章拆开，导入时选择用途。

- **拆解与仿写**：选「参考小说」，AI 拆解它的结构、提取文风、反推章节蓝图，生成仿写约束，供你后面写作时参考。参考小说只进知识库和拆解结果，不会混进你的正文。
- **导入原稿续写**：选「我的原稿」，你已经写好的章节按章节号导入为定稿，AI 续写后面的章节时会接着前文的人物和情节走。可以勾选「同时反推设定、架构、角色和蓝图」，蓝图只为还没有蓝图的章反推；其余反推只补空白，和已有内容不同的结果列成建议，由你逐条采用。导入停下后，点「继续导入」接着跑完，已提交的批次不重做。
- **段落续写**：正文里选中一段文字，点工具条上的「续写」，AI 接着这段往下写。
- **改写**：整章改写用「修稿」，写下你要改的方向，也可以勾选审稿意见，修稿结果按段落和原稿对比，由你逐段决定用哪一版。改一小段时，选中文字后用工具条上的润色、扩写、改成对话，或「按意见改」写下具体要求。

### 设定与架构：先把故事立起来

设定页写下类型、受众、写作语言、总章数和每章字数。架构页分四节：故事前提、角色名单、世界观、情节大纲。每一节都可以让 AI 生成，也可以自己写。四节都确认后，再进入章节蓝图。

![架构页：故事前提、角色名单、世界观、情节大纲四节都已确认](docs/assets/readme/v130-zh-architecture.webp)

角色名单和架构放在一起编辑。每个角色有基础设定、当前状态和关系图谱。角色卡可以粘贴或从文件导入。

![角色名单：左侧列出四个角色，右侧是主角林岚的档案](docs/assets/readme/v130-zh-cast.webp)

### 人物状态与关系时间线：写到第几章，人物就是第几章的样子

角色页的当前状态上方有一行「时间线 · N 处变化」。展开后按章列出状态和关系的变化与来历，来自定稿的记录可以看原文。手改状态时，可以指定从第几章起生效。

- 写或重写第 N 章时，提示词里的人物状态和关系按第 N 章的时间线取，不用最新值。回头补写前面的章，人物不会提前知道后面才发生的事。
- 定稿时顺带记下人物关系的变化，不多发请求。和你的设定不一致时，角色页的待处理建议里出现一条，可以「采用」「保留原设定」或「以后再说」。
- 生成蓝图时模型提出的新角色和关系，也进待处理建议，由你逐个新建、对应已有角色或不采用。

### 章节蓝图：动笔前先想清楚每一章

蓝图页逐章列出规划。每章写清主角小目标、冲突与转折、悬念钩子和出场人物。蓝图可以由 AI 按章节范围分批生成，中断后可以接着生成。

主按钮是「写第 N 章」。旁边的小弹层只放这一次写作的选项：用哪个模型，要不要补一句作者指导。想连写几章，用「批量创作」，一次最多 10 章。

![蓝图页：选中第 3 章「雾钟」，「写第 3 章」的写作选项弹层已打开](docs/assets/readme/v130-zh-blueprint.webp)

蓝图有两层检查，都不挡写作：

- **保存时的提示**：AI 生成的蓝图里两人关系和时间线相反，或安排了已死的角色，蓝图页给一行提示并写明依据。点「这是有意安排」可以按章或全书豁免。
- **「AI 检查」**：点一次发一次模型请求，对照人物时间线检查未定稿章的蓝图，结论按章列出。需要先有人物时间线，并保存蓝图。书很长、未定稿蓝图一次放不下时，只检查前面的章节，结果里写着「检查到第 N 章」。

### 伏笔线索：按到期章节提醒

「剧情与伏笔」页按章节记下主线、支线和伏笔在哪一章埋设、推进或回收。

- 写正文时，书童从到期、逾期和你指派到本章的线索里选出本章要推进或回收的任务，写进提示词并标明是否逾期，审稿时核对。
- 写作弹层里有一行「本章要处理 N 条线索」，可以「延后一章」或「延后三章」，也可以撤销。还没到期的线索可以提前「本章推进」。
- 审稿判定某章已回收的线索，定稿后点「确认已回收」记入线索。回收章超出全书规划章数的线索会被标出来。

### 正文：写稿、审稿、修稿、定稿

正文单章视图把一章从待写带到定稿。AI 写出草稿后，你可以直接改，也可以让 AI 审稿。审稿报告列出每条意见，你逐条勾选或忽略，也可以加上自己的意见。修稿结果以差异给你逐段确认，不会直接覆盖原稿。确认无误后定稿。

![正文单章视图：左侧是设定、架构、蓝图、正文四步流程，中间是第 3 章正文，右侧是审稿报告](docs/assets/readme/v130-zh-chapter.webp)

写作时，AI 拿到的是这一章的蓝图、相关角色、世界观、前文摘要、上一章全文和本章要处理的线索，而不是整本书的聊天记录。

- **批注统一修改**：选中正文点「添加批注」。一章里加好多处批注后，点「统一修改（N）」交给模型一起改。结果用红色标删除、绿色标新增，每处可以编辑、重新生成或接受，也可以「接受全部」。章节页可以查看「批注历史版本」。
- **键盘写作**：Tab 插入两个全角空格作为段首缩进，写一章的全过程可以只用键盘完成。Ctrl/⌘+F 在正文里搜索。

### 定稿后处理、重新打开修改与回收站

每章定稿后，书童把定稿正文导入知识库，生成章节要点，更新角色状态和关系。后处理失败或被取消时，正文已经保存，没做完的步骤可以重试。

- **重新打开修改**：已定稿的章点「重新打开修改」，当前定稿复制成一份重开稿，照常编辑、审稿、修稿。定稿确认框先列出这次替换对后续章节、角色状态和线索确认的影响。原定稿留在版本历史里，标为「已被替换的定稿」，只读。
- **检查后续蓝图**：替换定稿后，AI 给还没定稿的后续章提修改建议，写明依据和新旧对比，你逐条「接受」或「不用」。它只改蓝图，不改正文。
- **回收站**：在定稿章节点「删除正文…」，正文和它的全部版本进回收站，可以「恢复」或「彻底删除…」。蓝图的「删除此章…」和草稿的「删除这一稿…」不进回收站，删了不能恢复。删掉中间一章后，可以在原位置「重写第 N 章」。

### 知识库与检索：写稿时自动取材

- 导入参考资料（.txt、.md）。定稿正文在定稿后处理时自动进知识库。
- 有向量模型时用语义检索。向量模型是「设置 → 检索模型」里配的模型；没配时，如果默认模型支持向量（包括没有标注用途的旧配置），书童用默认模型做向量。两者都没有时，用本地全文检索，中文查询会拆成词，能找到只含部分词的段落。
- 「设置 → 检索模型」里可以选配「重排模型（可选）」：先多召回一些段落，重排后再取最相关的。重排没成功时按原顺序显示。
- 补写中间的章时，检索不返回这一章及之后章节的定稿正文，避免提前写出后文。

### 运行侧页：看清 AI 正在做什么

所有生成任务都在运行侧页里，分进行中、历史、诊断三页。写作时可以实时看到输出，随时取消。批量创作可以暂停。一步连续 15 秒没有进展时，卡片会写明已等多久。

生成失败时，已经写出的文字会留成恢复卡片，可以采用、复制或「不再恢复」。书童在后台时，写作、审稿、修稿、定稿和批量创作结束会弹系统通知，可以在「设置 → 外观」关掉「在后台时通知我」。

![运行侧页：正在写第 3 章，实时输出逐句出现](docs/assets/readme/v130-zh-run.webp)

### 版本、导出与备份

- **版本历史**：每章的历次稿件都留着，可以和当前稿对比，也可以回退成一份新草稿。
- **导出**：合并 Markdown、分章 Markdown 或 TXT。
- **备份**：把作品打包存到本机，或备份到你绑定的 WebDAV 云端。恢复时总是另存为一份新副本。

### 写作 Skill：导入你自己的写作规则

在设置的「写作 Skills」页，可以从本机选一个 Skill 文件夹或单个 SKILL.md，也可以填 GitHub 上的 Skill 地址，导入提示词型的写作 Skill，比如「去 AI 味」、某种文风或某类题材的写法。SKILL.md 引用的 references 文本会一并装入。安装前软件会先读取并展示内容，由你检查后再安装。装好后把它绑定到规划、写稿、审稿或修稿阶段，之后这一阶段的生成都会带上它。

只支持自包含的 SKILL.md 提示词。脚本、hook、子代理和工具调用这类内容不会被安装，Skill 不能在你的电脑上执行代码。

### 深色主题与中、英、日界面

外观有浅色和深色两套。界面支持中文、英文和日文。日文界面目前是第一阶段：界面框架和报错是日文，其余文案仍为英文。作品的写作语言可以选中文或英文。

![深色主题下的正文单章视图](docs/assets/readme/v130-zh-chapter-dark.webp)

## 和通用 AI 聊天写小说有什么不同

用聊天窗口写长篇，常见的问题是前后矛盾、忘了伏笔、改了一章后面全乱。书童把这些交给作品数据，而不是交给一段越来越长的对话：

- **上下文按章组装**：每章给 AI 的是这一章需要的蓝图、角色、世界观、前文摘要、上一章全文和本章要处理的线索，不需要把整本书塞进一次对话。
- **人物状态按章取值**：写第 N 章用第 N 章时的人物状态和关系，补写前面的章不会剧透后文。
- **伏笔有到期日**：本章要处理的线索写进提示词，审稿时核对，回收后由你确认。
- **改动有影响清单**：替换定稿前列出影响范围，之后可以让 AI 只改后续蓝图。
- **AI 不直接覆盖你的文字**：修稿、批注修改、反推建议、关系变化都以差异或建议出现，由你接受。
- **作品在本地，模型自己选**：数据存在本机 SQLite 数据库和作品文件夹，模型可以是云端 API，也可以是本机模型。

## 支持的模型与服务

书童不提供模型，也不代管额度。你在设置里填上自己的服务地址、模型名和 API Key。软件支持三种调用协议：

- **OpenAI 兼容协议**：Chat Completions 接口兼容的服务都可以用。
- **Gemini 原生协议**：Google Gemini。
- **Anthropic 协议**：Messages 接口兼容的服务，例如智谱的 Anthropic 接口。

设置里内置了这些服务商的预设：

| 服务商 | 协议 | 说明 |
| --- | --- | --- |
| DeepSeek | OpenAI 兼容 | 预设地址 `https://api.deepseek.com` |
| SiliconFlow（硅基流动） | OpenAI 兼容 | 预设地址 `https://api.siliconflow.cn/v1` |
| BigModel（智谱） | OpenAI 兼容 | 预设地址 `https://open.bigmodel.cn/api/paas/v4` |
| BigModel（智谱 Anthropic） | Anthropic | 预设地址 `https://open.bigmodel.cn/api/anthropic` |
| OpenAI | OpenAI 兼容 | 预设地址 `https://api.openai.com` |
| xAI（Grok） | OpenAI 兼容 | 预设地址 `https://api.x.ai/v1` |
| Google Gemini | Gemini 原生 | 预设地址 `https://generativelanguage.googleapis.com` |
| Ollama（本地） | OpenAI 兼容 | 模型跑在你自己的电脑上 |
| NovelAI | OpenAI 兼容 | 最小兼容支持，未用真实账号完整验证 |
| 自定义 | 三种协议任选 | 填任意兼容服务的地址 |

「自定义」只是在上面三种协议里换地址、模型名和凭据，不是任意 HTTP 接口。Azure、KoboldAI 原生接口等需要单独的适配器，换个 URL 不能保证能用。

- **模型列表**：填好地址和 API Key 后，自动获取端点的模型列表，也可以直接输入任意名称。模型名填成本机模型文件路径（例如 llama.cpp）也可以。
- **上下文窗口**：选中模型后自动填上下文窗口，并标出来源（来自服务商、内置资料、默认值、你填的或实测）。写单章正文时，如果服务商以超长拒绝，且书童能从报错里读出真实窗口，就记下这个窗口，缩减参考材料后自动重写一次。
- **分工模型**：在「设置 → 高级 → 分工模型」里，给规划、写稿、审稿、修稿、定稿后处理分别指定模型，没指定的跟随默认模型。
- **检索模型**：知识库的语义检索需要一个支持向量的模型。可以在设置的「检索模型」里单独配置，没配时支持向量的默认模型会顶替。重排模型可选。

### 用 Ollama 跑本地模型

```text
服务商：   Ollama（本地）或自定义
协议：     OpenAI 兼容
Base URL： http://127.0.0.1:11434/v1
API Key：  可以留空；界面要求时填任意占位值
模型：     你的 Ollama 模型名，例如 qwen3:14b
```

向量模型也用 `/v1` 地址。不要填 `http://127.0.0.1:11434/api`，那是 Ollama 的原生接口。

## 下载与安装

请只从 [GitHub Releases](https://github.com/EthanYoQ/Pagekin/releases/latest) 下载正式安装包。

系统要求：Windows x64，或 macOS（Apple Silicon 与 Intel 各有安装包）。另需一个模型服务：云端 API Key，或本机的 Ollama 等推理服务。

### Windows x64

```text
ai-novel-writer-setup-<版本号>.exe
```

1. 运行安装程序。升级时安装程序只更新应用本身，不会删除作品、角色卡或设置。重要作品仍建议先备份。
2. 安装后，应用可以在「设置 → 关于与更新」里检查更新。发现新版本时先提示你，你点「下载更新」后才开始下载，下载完再选择立即重启更新或稍后。
3. 旧版便携 ZIP 不能自动获得更新器，需要手动安装一次正式安装包。

当前安装程序未进行代码签名。Windows 可能提示未知发布者。请确认下载页面是本项目的官方 GitHub Release 后再继续。

### macOS（Apple Silicon 与 Intel）

```text
ai-novel-writer-mac-arm64-<版本号>-installer.dmg
ai-novel-writer-mac-x64-<版本号>-installer.dmg
```

1. `arm64` 适用于 Apple Silicon Mac（M1、M2、M3、M4 等）。`x64` 适用于 Intel Mac。
2. 把 DMG 里的应用拖进「应用程序」文件夹后启动。应用会提示新版本，但不会在 macOS 上自动下载或替换程序。更新时打开官方 Release 页面，手动下载对应架构的安装包。
3. 两个安装包均为 ad-hoc 签名，且均未使用 Developer ID 签名或公证。Gatekeeper 阻止打开时，先确认来源是本项目的官方 GitHub Release，再在 Finder 里按住 Control 点按应用并选择「打开」，或在「系统设置 → 隐私与安全性」里允许打开。

## 数据与隐私

| 数据或行为 | 存放位置或去向 |
| --- | --- |
| 作品、角色、蓝图、草稿和定稿 | 你的作品文件夹和本地 SQLite 数据库。 |
| 用「删除正文…」删掉的定稿章节 | 进当前作品的回收站，彻底删除前都可以恢复。 |
| 生成失败的恢复卡片 | 只存在当前作品的本地数据库里，不会自动变成草稿或定稿。 |
| 导入的参考资料 | 存在本地作品里。有向量模型时（含默认模型顶替），导入时资料段落会发给它做向量化。 |
| 本地模型请求 | 发给你配置的本机或局域网推理服务。 |
| 云端模型请求 | 提示词和上下文发给你选择的服务商。 |
| 知识库导入与检索 | 有向量模型时（含默认模型顶替），导入资料和定稿正文的段落、以及检索词发给这个模型；配了重排模型时，检索词和召回的段落发给重排模型。两者都没有时，检索只在本地进行。 |
| 模型配置与 API Key | 保存在本机应用数据目录的 `ai-novel-writer` 文件夹里（Windows 为 `%APPDATA%\ai-novel-writer`，macOS 为 `~/Library/Application Support/ai-novel-writer`）。请保护好系统账户，不要分享这个文件夹。 |
| 应用偏好 | 与模型配置在同一个文件夹里。 |

早期版本把配置存在 `~/.vela`。新版本启动时会把它复制到上面的文件夹，原目录不改动。

软件本身不提供模型账号、云端生成服务或运营消息推送。联网检查更新只读取公开的 GitHub Release。

## 常见问题

### 书童免费吗？

免费。软件以 GPL-3.0 协议开源。调用云端模型产生的费用由你和模型服务商结算，与本软件无关。用 Ollama 跑本地模型则不需要付费给任何服务商。

### 用 AI 写小说，书童支持哪些模型？

兼容 OpenAI Chat Completions 接口的模型都可以接，例如 DeepSeek、通义千问（经硅基流动）、智谱 GLM、OpenAI、xAI Grok。Google Gemini 走原生协议，智谱的 Anthropic 接口走 Anthropic 协议。本机模型可以用 Ollama。生成质量取决于你选的模型，软件不对模型输出质量作保证。

### 作品数据存在哪里？会上传吗？

存在你自己的电脑上：作品文件夹加一个本地 SQLite 数据库。需要模型的操作，例如写作、审稿、导入小说后的拆解和后处理，会把相关的正文、设定和上下文发给你配置的模型服务。有向量模型时（含默认模型顶替），知识库导入会把资料段落发给向量模型，检索会把检索词发给它；配了重排模型时，检索词和召回的段落会发给重排模型。想让私密资料不出本机，导入前要把用到的模型都换成本机模型，包括默认模型、「分工模型」里指定的模型、检索模型和重排模型；检索模型留空时由默认模型顶替。WebDAV 云备份只在你绑定 WebDAV 并发起备份时上传。

### 能不能离线写小说？

可以，前提是你用到的模型都在本机或局域网，包括默认模型、「分工模型」里指定的模型、检索模型和重排模型。检查更新、从 GitHub 导入 Skill、WebDAV 备份和云端模型需要联网。

### 能写多长的小说？前后会不会矛盾？

总章数由你在设定里填，没有固定上限。写每一章时，AI 拿到的是这一章的蓝图、相关角色、世界观、前文摘要、上一章全文和本章要处理的伏笔线索，所以不需要把整本书塞进一次对话。人物状态按章取值，蓝图可以用「AI 检查」对照人物时间线查矛盾。批量创作一次最多连写 10 章，可以多次接着写。

### 定稿后还能改吗？删错了章节怎么办？

能改。已定稿的章点「重新打开修改」，改完再定稿会替换原定稿，原定稿留在版本历史里。用「删除正文…」删掉的定稿章节进回收站，可以恢复。

### 能导入已经写好的小说接着写吗？

能。在书房的「小说拆解与仿写」里导入 .txt、.md 或 .epub，用途选「我的原稿」。已写章节导入为定稿，可以顺带反推设定、架构、角色和蓝图，再从下一章接着写。

### 支持英文或日文写作吗？

作品的写作语言可以选中文或英文，暂不支持日文写作。界面有中文、英文和日文三种，日文界面目前是第一阶段。

### 怎么升级到 1.5.0？

已经装了 1.1.0、1.2.x、1.3.x 或 1.4.x 的用户，会在应用内收到更新提示（macOS 需要手动下载新安装包）。用 1.5.0 打开过的作品会升级作品数据，之后 1.4.x 及更早版本打不开它，也恢复不了 1.5.0 导出的存档，所以升级前建议先备份重要作品。更早版本的项目，在书房点「导入」，选择「导入旧项目副本」，导入会生成一份新副本，原项目保持不动。

### 能导入 Skill 吗？比如去 AI 味。

可以。在设置的「写作 Skills」页选择本机的 Skill 文件夹或 SKILL.md，或填 GitHub 上的 Skill 地址，检查内容后安装，再绑定到写稿或修稿等阶段。只支持提示词型的 SKILL.md，不会安装或执行脚本。

### 助手聊天去哪了？

1.3.0 起的新界面暂时隐藏了助手聊天入口，以后会单独重新开放。写作、审稿、修稿等功能不受影响。

### Windows 或 macOS 提示安装包不安全怎么办？

Windows 安装包未签名，Mac 安装包只有 ad-hoc 签名、没有经过 Apple 公证，所以系统会提示。确认安装包来自本项目的官方 GitHub Release 后，按上面「下载与安装」的步骤允许打开。

## 当前限制

- 不保证任意第三方 API 只靠 URL 和 Key 就能接入，只保证已实现的三种协议和预设。
- 写作语言只有中文和英文。日文界面只翻译了界面框架和报错。
- 不替代作者的创意、事实核查和版权判断。AI 写出的内容需要你审阅。
- 不提供在线发布、阅读社区或云端模型账号。

## 从源码构建

需要 Node.js 22.14 以上和仓库指定版本的 pnpm。

```sh
git clone https://github.com/EthanYoQ/Pagekin.git
cd Pagekin
pnpm install --frozen-lockfile
pnpm dev
```

正式安装包由 GitHub Actions 云端构建。Windows x64、macOS Apple Silicon 和 macOS Intel 三个安装包各自通过资格检查后，才进入同一个 GitHub Release。文档权威层级、ADR 和开发规则见 [`docs/README.md`](docs/README.md)。Logo、配色和设计稿见[品牌包](docs/brand/README.md)。
