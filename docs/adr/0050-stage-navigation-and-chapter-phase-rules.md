# 流程脊导航、章节阶段与运行侧页的规则

2026-11-27，注释清理（#852）第 4 个 PR（src 其余，不含 shared、components、services/workflows）。

## 背景

`src/stores/navigation/` 下的 `stage-store.ts`、`stage-navigation.ts`、`stage-progress.ts`、`chapter-facts.ts`、`navigation-intents.ts` 与 `page-tabs.ts` 把 ADR-0021 的分阶段流程落成状态与导航规则。注释里写着落点怎么选、请求怎么清、章节处在哪一步怎么判，这些口径只靠函数体读不出来。

## 决定

所有跨层导航都经唯一入口 navigate，调用方只描述意图，由 stageNavigate 决定落到哪些界面状态。流程脊与单章视图读同一份章节事实（审稿与修稿记录），章节处在哪一步由这份记录与稿状态一起判定，读失败的稿保留原值。打开作品落在第一个未完成的阶段，设定齐了且已有蓝图或正文时落在正文，不把作者拉回没写完的架构页。写作与重读请求、选区续跑请求都只属于发出时的那次打开，换作品或重新打开即清掉。设置页开着时导航先确认未保存的输入。下面按文件列出各条口径。

## 渲染端其余口径（注释清理 #852 第 4 个 PR，src 其余）

### `src/stores/layout-store.ts`

- `ChapterWritePrefill`：写作此章的参数（取自蓝图），章号由 chapter 意图给出。
- `settingsSection`：设置页当前的分区：打开时由入口指定，作者点左侧分区时更新。

### `src/stores/navigation/__tests__/chapter-phase.test.ts`

- 几章都在写时落在最后一章在写的：定稿后新建空草稿的章也算在写。

### `src/stores/navigation/chapter-facts.ts`

- `isRevisionSourceCurrent`：修稿生成时冻结的源稿与这一稿现在保存的样子相同，才能合并；旧修稿没有冻结源，只能查看。
- 只有有待合并修稿时才读正文：判断修稿生成之后这一稿的保存内容变没变。
- `refreshChapterFacts`：重读这几稿的审稿与修稿记录，写进 stage-store 的 chapterFacts。流程脊（打开作品与每次刷新）和单章视图（打开、合并、 丢弃修稿、保存了有待合并修稿的稿）都调它，所以两边看到的是同一份。同一稿只认最后一次请求，但还没有记录的稿先收下 较早请求的结果：打开作品时单章视图对落点那一章的读取会取代流程脊那批里的同一稿，流程脊不能因此缺这一章。读失败的稿保留原值。

### `src/stores/navigation/navigation-intents.ts`

- `WorkStage`：作品流程脊的四个阶段，顺序即创作顺序。
- `NavigationIntent`：跨层导航意图。调用方只描述要去哪里，由 stageNavigate 决定落到哪些界面状态。
- `kind: 'stage'`：不带 stage 表示回到作品的流程脊，不切换内容页。
- `kind: 'chapter'`：带 write 时打开这一章，并由单章视图弹出写作此章的弹层。
- `navigate`：唯一的跨层导航入口。

### `src/stores/navigation/page-tabs.ts`

- `PAGE_TABS`：阶段与资料页对应的标签。正文与知识库没有固定标签，由各自的页面处理。

### `src/stores/navigation/stage-navigation.ts`

- `enterWork`：回到作品：离开书房、退出沉浸。不收起搜索：搜索是模态层，作者在里面选中一项时它自己先关； 搜索开着时还能到这里的只有自动跳转（打开作品后的落点、工作流开始时打开运行侧页），它们不该关掉作者正在输入的搜索。
- `chapterDrafts`：草稿 store 已按这次会话完整载入时直接用它；否则单独读这一章，不依赖可能被新一轮 loadAllDrafts 作废的载入。
- `chapterNavigationEpoch`：章节导航的序号：作者每点一次章、阶段或资料页就变。自动打开在等待期间看到它变了，就是作者已经去了别处。
- `chapterPlanTabId`：待写章的单章视图标签：还没有稿，所以没有 filePath，按章号区分；与其他正文标签一样按作品加后缀。
- `openChapterPlan`：打开待写章的单章视图：显示本章蓝图与「写作此章」。草稿生成后换成草稿标签。
- `openChapter`：打开一章：已有这一稿的标签就直接切过去；否则读出正文开新标签。待写的章还没有正文，打开它的单章视图，那里有「写作此章」。 连续点几章时只有最后一次生效；读取失败时提示作者，而不是点了没反应。 自动打开传入 stillIntended，读取期间它变成 false 就放弃。返回这一章最后有没有切到前台。
- 已经有稿的章没有写作此章；写作请求（比如定稿后自动打开下一章）落空，不能留到别处再弹出。
- 写作与重读请求可能在接手的页面挂载前一直留着（比如作者在书房里）；换作品或重新打开后，它们不能落在新作品的同一章上。 审稿侧页按稿的 filePath 归属，稿 id 在各作品里各自递增会撞，换作品或重新打开时一并收起。
- `openManuscript`：正文阶段本身没有页面，落到当前该写的那一章；还没有任何章时先去蓝图。
- `stageNavigate`：各意图的落点。设置是内容面板里的设置页。 写作此章打开这一章的单章视图，由那里的写作按钮弹出写作弹层；参数取自蓝图，不再弹旧的创作对话框。
- 设置页开着时换分区会卸掉当前分区的输入，与设置页里点侧栏换页一样先确认。
- `staysInSettings`：去具体的阶段、资料页或章节，或从书房进作品，都会收起设置页，有没保存的输入时先确认； 已在作品里时只回到作品（打开作品后的默认落点）或打开运行侧页，设置页留着。
- 去别的阶段或资料页是作者新的选择：还在读正文的那一章读完后不再抢回标签。
- 回到作品只收起运行侧页。审稿侧页属于单章视图：打开作品落在已审稿的章时它按这一章默认展开，不能随后又被收起。

### `src/stores/navigation/stage-progress.ts`

- `SetupField`：设定的必填项，与设定画板一致：一段核心大纲，加类型、篇幅、目标读者三项。
- `ARCHITECTURE_SECTIONS`：架构的四节：故事前提、角色名单、世界观、情节大纲。 ia.md 写的是「4 节均已确认」，但产品里各节没有确认状态（ArchitectureConfirmDialog 只是生成前勾选步骤）， 所以取架构页徽标同一个判定：前提、世界观有内容，角色名单已就绪，情节大纲按分批检查点全书写完且没有中断的批次（checkArchConfirmed）。
- `StageProgress`：完成为实心勾选圆，进行中为按比例填充的进度环，未开始为虚线圆。
- total 是设定里的规划章数；至少 1 章蓝图即完成，planned / total 只作进度说明。
- `ChapterPhase`：一章所处的位置：待写、草稿（待审稿）、已审稿（待修稿）、有修稿待合并、已修稿（待定稿）、定稿。
- `ChapterFacts`：一稿走到哪一步要看的审稿与修稿记录，由 chapter-facts 读出；流程脊与单章视图读同一份。
- `mergeable`：可以合并的待合并修稿 id，按生成先后。
- `stale`：不能再合并、只能查看或丢弃的待合并修稿：edited 是生成后正文或稿状态变了，unsourced 是旧修稿没有记下生成时的源稿。
- `latestReview`：这一稿最新的审稿；cycleStatus 是它所属复验周期的修稿进度，旧审稿与合并后的自动复验没有周期。
- `chapterPhase`：一稿（未归档）走到哪一步。数据库里没有代码把草稿设为 reviewed：审稿只新增审稿记录，合并修稿才把稿改成 revised， 所以 reviewed 状态与草稿一样看记录。有可合并的修稿就停在合并；过期的修稿不占主流程。 已修稿的稿只有在最近一次合并之后又审过稿、且那份审稿的复验周期还没合并时才算已审稿：合并前的审稿（比如审稿后直接修稿合并） 与合并后的自动复验都不算。合并与审稿落在同一秒时按合并在后处理。
- `draft`：打开这一章时载入的稿：有定稿之后才建的未归档草稿时取它，否则取定稿，再否则取最新的未归档草稿；待写章为空。
- `hasFinal`：这一章有定稿；当前稿可能是定稿之后新建的草稿。
- `chapterFacts`：按稿 id 的审稿与修稿记录；还没读出的稿按状态估计。
- `count`：与主进程的作品概览同一口径：章数、字数都得是正的安全整数。
- `begun`：这一章动过笔：有定稿（之后又新建了空草稿也算），或当前稿有正文。只有空的当前稿不算；没记字数的旧稿按有正文算。
- `deriveStages`：四个阶段的状态，顺序固定为设定、架构、蓝图、正文。完成判定按 ia.md：设定必填项齐全，架构四节都有内容， 蓝图至少 1 章（分批规划的作品不会因为没规划完就一直停在蓝图），正文按章统计。 定稿章数与章节列表同源：定稿之后又建了草稿的章按草稿算，不计入定稿。
- `createdAfterFinal`：这份稿在定稿之后才建（版本历史「回退到此版本」会在定稿章上新建草稿）。旧版本的草稿箱允许给较旧的版本定稿， 所以不能按版本号比：定稿前就有的更高版本不算。定稿时间取定稿稿的 updated_at（定稿后不可再改）； 两者同为数据库 datetime('now') 的写法，可直接按字符串比；同一秒内分不出先后时退回按版本号。
- `focusChapter`：打开作品、书房「继续写作」与点「正文」打开的章：几章都在写时取最后一章在写的（用户决定）， 其次最早一章还没动笔的（待写或只有空稿），都没有时取最后一章定稿。
- `landingStage`：打开作品时落在第一个未完成的阶段；四个阶段都完成时落在正文。设定齐了且已有蓝图或正文时落在当前写作位置（正文）： 架构没写完（比如大纲分批只写了一部分）不把作者拉回架构，有正文没有蓝图也不落到空的蓝图页；流程脊与架构页照旧显示部分完成。
- `runningChapters`：工作流正在写的章：运行声明的资源里形如 chapter:<章号> 的那些。 批量创作一次声明整批章，但按章逐步写（第 i 步写第 i 章），只有当前步骤那一章在写，其余还在排队；暂停时没有章在写。
- `StepWait`：on 为 model 时一次模型请求还没结束；为 step 时拿不准在做什么，界面只说这一步还在进行。

### `src/stores/navigation/stage-store.ts`

- `RunSheetTab`：运行侧页的分页：进行中（步骤、实时输出、等确认、可恢复）、历史、诊断（宽版：日志与模型调用）。
- `StageSheet`：内容区右侧的按需侧页，同一时间只开一个。运行侧页的 runId 是要看的那次运行：还在运行就在「进行中」里定位，已结束就在「历史」里展开它。 审稿侧页由单章视图摆出，内容是 filePath 那一稿的审稿报告；换到别的稿时它不跟过去，各稿按自己的阶段决定是否默认展开。
- `StagePalette`：命令面板：commands 是搜索与跳转（⌘K / Ctrl K），chapters 只查章节（⌘P / Ctrl P）。
- `StageWork`：流程脊从项目数据派生状态时用到、而 project-store 与 draft-store 里没有的两项。
- `focus`：沉浸写作：只留正文与章节动作条。
- `closingTabId`：有未保存修改、等作者确认是否放弃的待关闭标签。
- `writeRequest`：要为这一章打开写作弹层（定稿后打开下一章等）；挂着这一章写作按钮的页面接手后清空。只属于发出时的那次打开，换作品或重新打开即清掉。
- `chapterRequest`：审稿或修稿刚生成，要这一稿的单章视图重读数据；视图接手后清空。只属于发出时的那次打开，换作品或重新打开即清掉。
- `selectionRequest`：运行侧页「继续原选区任务」的请求；编辑器挂着时接手并清空，换作品或重新打开即清掉。
- `coveredProseFile`：单章视图的正文被修稿合并或批注修改审阅盖住的稿；选区续跑不交给它。视图卸载或两者都收起即清空。
- `chapterFacts`：各稿的审稿与修稿记录（按稿 id），流程脊与单章视图据此判断一章走到哪一步；只属于读出它的那次打开。
- `spineFacts`：流程脊为这次打开读完过一遍各稿的审稿与修稿记录。没读完时流程脊不列阶段与章节，章节阶段不会先按稿状态估计再改。
- `mergeChoices`：修稿合并里作者的逐段选择与各段文字，合并视图卸载后重新打开接着用；合并或丢弃修稿时清掉。
- `useStageStore`：外壳的界面状态。书房与作品的切换在 layout-store 的 sidebarView。

### `src/stores/open-draft-tab.ts`

- `openDraftTab`：读出一稿正文，打开它的标签或切到已开的标签。章节列表与导航都走这里。 读取期间项目会话变了，或调用方已不再需要这次打开（stillWanted 返回 false）时放弃，返回 false。

### `src/stores/project-store.ts`

- 默认落点与提交同步落下，之后作者的导航不会被它改回。
