# 上下文窗口的取值只写在一处，选中模型时自动拉取

2026-11-08，#279。本 ADR 补充 ADR-0026，不改它的原文。

## 背景

维护者要求配置模型时自动得到窗口数字，用拉取而不是本地穷举，不明模型设小一点；大部分作者对报错和调整没有耐心。

现状有两个问题：

- 服务商明明声明了窗口（Gemini 的 `inputTokenLimit`、Anthropic 的 `max_input_tokens`），解析时被丢掉。本机的 Ollama 和 LM Studio 从不询问。
- 优先级写了多份，表单、额度各算各的。

## 决定

1. **优先级只写在 `resolveContextWindow`：手填 > 拉取 > 预设 > 默认。** 设置页和可选材料额度都读它。默认一般 32,768，Ollama 4,096。旧档案没有来源记录时，与预设相同的数算内置资料，不同的算作者填的。
2. **只在作者拉取列表或选中模型时请求。** 启动时和后台不请求，旧档案不回填，下次选中时更新。
3. **本机服务只认实际运行值。**
   - Ollama 先读 `/api/ps` 的 `context_length`，再读 `/api/show` 的 `parameters` 里的 `num_ctx`。`model_info` 的 `<架构>.context_length` 是模型上限，未加载时实际窗口往往小得多，不采用。
   - LM Studio 只读 `/api/v1/models` 已加载实例的 `config.context_length`，`max_context_length` 同理不采用。
   - 地址由档案自己的 baseUrl 换路径得到，不跟随重定向，凭据不会发往别处。
4. **读不到不打扰作者。** 超时、401、格式不对都静默落到预设或默认，模型照常保存和写作，不加必填项、弹窗或新报错。
5. **设置页在窗口旁标来源：来自服务商、内置资料、默认值、你填的。** 默认值不写进档案，只作占位显示。作者填数变「你填的」，清空回到自动。

## 未决

租约证据（`resolveModelExecutionCapabilityEvidence`）仍是预设压过手填，本 ADR 没有改它。ADR-0026 决定 3 记录了原因：它进收据、恢复时深比较，改了会让升级时的在途运行报错。窗口对发送内容的影响只经过可选材料额度，额度已按决定 1 取值，所以作者实际得到的材料不受这处差异影响。

## 后果

- 窗口小的本机模型配大的最大输出时，可用输入可能为 0，可选材料全不放，见 ADR-0026「后果」。作者不用处理，写作照常。
- Ollama 超长时截断还是报错，官方文档没有写明，本机也没有实测。4,096 的默认值不依赖这个结论。
- LM Studio 原生接口与 `/v1` 同地址，依据是官方文档示例，没有实测。
