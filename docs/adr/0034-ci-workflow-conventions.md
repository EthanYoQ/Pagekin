# CI 工作流的约定

2026-11-26，注释清理（#852）第 1 个 PR（.github）。

## 背景

`.github/workflows/pr-ci.yml`、`macos-daily-tests.yml`、`dsh-plugin-ci.yml` 里原有一批解释「这个步骤为什么这样写」的注释。本 ADR 把它们迁到一处，工作流里不再留注释。发布资格与晋升工作流另见 ADR-0033。

## 决定

### 一、PR CI

1. 分支保护要求每个 PR 都有桌面检查，所以纯文档改动不跳过整个工作流，只跳过其中的 Windows 分片。
2. 变更分类器在 PR 合并提交上取 base 分支的副本：`HEAD` 是 PR 合并提交，其第一个父提交是 base 分支顶端；改动分类器本身的 PR 不能被它自己的副本裁决。
3. 权限最小化：不可信的 PR 代码在没有仓库写权限、没有模型凭据的情况下测试。
4. 工具链（pnpm 等）与既有 Windows 发布工作流保持一致，避免两处漂移。
5. 下载 Electron 二进制的步骤跳过安装脚本：GitHub 的发布文件下载偶发 5xx，这样重试只包这一次下载，lockfile 错误不被重试。
6. 编译步骤只编译，不为 Electron 重新构建、不打安装包、不发布。
7. 每日门禁刻意不上传产物、不做依赖缓存，使它与保留的、经发布资格的 Windows/macOS 包分开。
8. `master-guards`：两个各自绿的 PR 合并后可能让守卫测试变红，PR 检查看不到，所以只在合并后报警，不拦 PR。

### 二、macOS 每日测试

1. PR CI 只跑 Windows；这里每天在 master 上跑一次 macOS，让 macOS 特有的失败不必等到发版前的打包资格构建才暴露。
2. 定时取 UTC 18:17（北京时间 02:17），维护者早上能看到结果；避开整点，因为整点的定时任务扎堆会排队延迟。`schedule` 只在默认分支触发。
3. 运行在 `macos-15`（arm64），与 `macos-arm64-cloud-build.yml` 同一镜像，这里复现的失败与发版打包的环境一致。
4. 超时 45 分钟：该 runner 上全量 vitest 约 446 秒（实测一次），再加安装与 helper 编译，45 分钟留足余量。
5. 下载 Electron 二进制重试只包这一次下载，免得每天出假红。
6. `/var` 是 `/private/var` 的别名，安全文件层按真实路径比对，所以测试临时目录要先解析为真实路径。

### 三、dsh 插件 CI

测试步骤不重新构建：前一步已经构建并验证了同一份字节。
