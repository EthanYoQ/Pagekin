# Windows 发布闸进程监控的判定原则

2026-11-26，注释清理（#852）第 1 个 PR（scripts）。

## 背景

`scripts/monitor-win-release-gate.ps1`（约 4400 行）与 `smoke-win-app.ps1` 监控发布闸里每一个子进程的生命周期：异常退出与错误窗口都会让发布步骤失败。electron-builder 的 NSIS 安装与卸载程序却会故意让探测命令以退出码 1 结束，这类「正常的否定」必须能与真失败区分。这些判定原则原先写在脚本里约 60 处注释中，本 ADR 收拢它们。`monitor-win-release-gate.ps1` 的整份字节按 sha256 钉在 `electron/__tests__/package-contract.test.ts` 里，改任何字节（含注释）都会让该测试变红，所以该文件里的同样说明暂时保留，等钉死解除后再删；其余脚本里的说明已随本 PR 删除。产品改名带来的新旧名并存见 ADR-0022。

## 决定

### 一、监控机制

1. **两个持久通道都必须存在，才放行被门控的目标。** Job Object 拥有完整后代集合、其完成端口保留生命周期事件；WinEventHook 保留桌面轮询快照可能漏掉的短命错误窗口。被门控的启动器先纳入 Job Object、再发布 `monitoring`，此后它创建的每个命令与后代都进入持久生命周期流。
2. 基线之前已存在的窗口，其事件属于基线纪元，不属于第一个发布步骤。已挂钩的事件即使对话框在普通桌面快照之前消失也保留；当前快照用来补无障碍事件缺失或延迟的窗口。
3. Job Object 没有送来终态通知时，继续经正常的退出后静默期排空，并在步骤被标记完成之前 fail closed。错误窗口检测须在进程退出后连续运行满五秒，期间保留完整的历史 PID 与启动时间集；最终的桌面快照也算在静默区间内。
4. C# 完成端口工作线程在仍持有原生进程句柄时捕获镜像路径、命令行等字段；PowerShell 循环里不得做慢的 CIM 调用，否则会延迟排空下一个短命子进程事件，丢掉这条记录本要保留的命令行证据。
5. 状态发布的重试只是传输卫生（Node 的状态读取器可能短暂持有 Windows 共享锁），不参与进程与错误观测，也不扩大原子监控边界。每步只写一份汇总，无论哪条终态路径或步骤切换先到。
6. 完整命令行只在内存里供 NSIS 探测分类用；诊断是可下载的产物，所以只持久化「捕获成功」这一事实，绝不写参数载荷；失败文本只含步骤、PID 与退出码。

### 二、身份绑定（一切例外的前提）

1. PID 会复用。凡是例外，都把进程绑定到 PID、创建时间与规范镜像路径三项；缺记录、PID 复用、环、祖先过深都 fail closed；没有可信创建时间的子进程无法证明属于该进程实例，不跟随被复用的父 PID，也不把替代进程的子进程纳入应用树；`ParentProcessId` 只对确切的进程实例有意义。
2. 镜像路径必须是监控器捕获的绝对路径：在规范化之前就拒绝相对的同名假冒；不凭 8.3 短名的文字相似接受路径，文件仍存在时用 kernel32 展开别名，展开失败则保留绝对拼写、交给严格的 TEMP 包含测试去拒绝未证实的别名。命令行通常必须把 `argv[0]` 绑定到捕获的镜像路径；32 位 NSIS stub 是窄例外（`$SYSDIR` 可能记成 System32 而镜像是重定向的 SysWOW64），但不得退化成 basename 匹配。nsExec 启动无空格路径的进程时可能去掉源模板 `argv[0]` 的引号，两种运行形式都绑定到捕获的完整路径，开关、空白与载荷仍逐字节字面。
3. 武装的闸根（Node 发布闸根）在放行之前只捕获一次并保持不可变身份；子进程的生命周期记录可能在该根退出之后才被消费，所以卸载程序例外必须保留这份不可变的 PID/启动时间/路径身份，而不是接受 Job Object 里任何同名助手链。完整的祖先链必须止于那个精确的根，无关的同名 NSIS 链不能冒充。

### 三、NSIS 探测命令的窄例外（都 fail closed）

1. electron-builder 的 NSIS 模板把三条探测命令的退出码 1 当正常分支：PowerShell 可用性、执行策略可用性、「INSTDIR 里没有进程」。这个例外只适用于安装程序烟测步骤，不适用任何一般的 PowerShell 进程。per-user 的 `FIND_PROCESS` 回退里，旧模板把 `tasklist` 管给 `find.exe`，26.15 加了 `/NH` 并管给锚定的 `findstr.exe`；`FilterArguments` 是 `cmd.exe` 在 `argv[0]` 之后重建出的命令行。
2. NSIS 卸载程序会先把自己复制到当前 TEMP 根（`~nsu*.tmp\Un_*.exe`），再从这个 helper 运行进程退出检查。这是**固定的产品链**，不是对任意临时可执行文件的 basename 豁免；发布启动器可能在启动 NSIS 卸载程序前加外壳包装，所以沿捕获的父身份链走，而不假定卸载程序是武装根的直接子进程。
3. 保持原来直接安装程序的检查完整不动；新增分支都是完整的、产品专属的卸载链，链上每条边都由 PID、创建时间与绝对镜像路径绑定，直接安装程序分支刻意保留其原分类语义。
4. 过滤子进程（`find.exe`/`findstr.exe`）必须是它自己的 `cmd.exe` 父进程命名的那个可执行文件，不能互借模板，也不能借别的产品可执行文件名；PID 本身会复用，所以关联键含创建时间与规范镜像路径，防止一个被验证的 `find.exe` 授权另一个 `cmd.exe`。
5. `cmd.exe` 的退出可能先于其 `find.exe` 子进程到达完成端口，终态通知也可能先于子进程完成记录，所以决定要延后到整批 `Drain()` 处理完；合法状态等一次后续 `Drain()` 加一小段关联宽限，让下一批送来匹配的 `find.exe`。畸形的特殊状态绝不静默放行发布；宽限后 `cmd.exe` 无进程退出仍没有身份绑定的 `find.exe` 子进程，就是真正的安装失败。
6. 矛盾的证据即失败，缺失的证据为「不可观测」，两者都阻断步骤，标签告诉后续调查者是哪一种。未证实的 NSIS 进程检查成员不能落进「结果所有者豁免」，因为根的结果无法拥有它的退出 1。
7. 武装根及其持久结果拥有选定的构建/安装/升级步骤的最终成败，其被识别的后代只是证据；其他步骤仍对每个异常后代的退出 fail closed。

### 四、原生更新器与历史升级

1. 原生更新器移交没有遗留控制记录：必须绑定到更新器拥有的 pending 根下那个唯一的最终 NSIS 产物，以及被捕获的旧应用父进程，不凭 basename 或近似相似的 `LOCALAPPDATA` 路径授权。唯一合法的旧卸载程序探测链是：被捕获的 E2E 旧应用 → 更新器拥有的 pending 安装程序 → `TEMP\ns<ASCII 字母数字>.tmp\old-uninstaller.exe`，每条记录都按身份绑定，防止被复用的 PID 或相似命名的临时 helper 继承例外。
2. 原生 `autoUpdater` 把更新器拥有的 pending 安装程序交给旧应用之后，Electron 可能报 `STATUS_BREAKPOINT`：这个例外独立于遗留桥，且只绑定确切的旧应用与确切的直接子官方安装程序身份，拒绝任何残缺、复用、漂移或歧义的进程链；不接受别的进程、别的退出码或预授权状态。
3. 历史 NSIS 升级把已安装的卸载程序复制到 `TEMP\ns*.tmp\old-uninstaller.exe`，其固定 PowerShell 探测以退出码 1 为正常否定；该分支刻意只限于同字节遗留桥的私有暂存安装程序（官方移交已被终止之后），每条祖先边都身份绑定。已绑定的历史 NSIS 进程在终止握手期间可能短暂发布无标题对话框，这不是观察到交互式安装向导的证据；`Stop-Process` 可能使确切绑定的安装程序先于其持久 Job Object 退出事件被消费而不再存活，须据已接受的终止控制来界定这段销毁空窗，而不信任可能被复用的 PID。

### 五、`smoke-win-app.ps1`

1. 根进程可能在两次普通轮询之间创建子进程再退出，所以对其历史谱系刷新一次，查询不可用时 fail closed，并保留任何存活子进程供诊断与清理；这次严格刷新刻意放在 `alive=0` 成功分支之前，不因根在两次普通子进程扫描之间退出就接受空的历史集。终态刷新是证明义务：CIM 查询不可用不是「已退出的根没有后代」的证据。
2. 保留已退出进程的 PID 与创建时间对，使迟到的 WerFault 命令行仍能归属产品；退出后的窗口监视器才是迟到错误对话框的权威。最终快照弥合最后一次轮询与验收之间的间隙，验收要求真实产品窗口在最终快照里仍可见；完整的健康观察区间只在真实产品主窗口首次出现之后才开始计。
3. `GetProcessById` 每调一次都枚举全机进程，按窗口逐个查时几百个窗口乘几百个进程要几秒，发布闸监视器每轮都拍快照，会慢到步骤完成超时；所以先取一次进程名表，表里没有的（之后才启动的）再单独查。
