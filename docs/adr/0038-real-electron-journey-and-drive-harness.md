# 真实 Electron 旅程与 drive 驱动的约定

2026-11-26，注释清理（#852）第 1 个 PR（scripts）。

## 背景

`scripts/redesign/drive.mjs` 与 `scenarios` 系列文件、`scripts/f0*-journey.mjs`、`*-startup-acceptance.mjs`、`network-proxy-journey.mjs` 等，用 Playwright 驱动真实 Electron，窗口在屏外、数据目录隔离、模型换成本机假服务。这些脚本里有大量「为什么这样等、这样判、这样隔离」的注释（约 600 处）。本 ADR 把其中的决定按主题收拢；每个场景自己的步骤描述不再重复。验证流程见 `.claude/skills/verify/SKILL.md`。

## 决定

### 一、隔离与清理

1. Electron 的全部可写根都落在 `parent` 下的一个新目录里；项目路径要短，原生存储有长度上限（Windows 原生存储预检要求作品根路径比证据目录短，测试作品放近 scratch）。用户的真实配置目录运行前后逐条比较，证明隔离目录之外没有写入。本机开着的书童约每 5 分钟刷新几个 Chromium 缓存文件的修改时间，这些变化不说明隔离失效，只记进 `externalWritesIgnored`；快照超过条目上限时报错，因为截断的快照会漏掉写入。
2. 外部写入与残留进程都要留着隔离目录取证；只有全部检查通过才删。删除一律走带有限重试的函数，应对 Windows 上短暂占用的 EBUSY、EPERM；失败返回错误码而不抛，清理失败不能打断结果写出与密钥扫描。
3. 退出：`close` 返回后 GPU、渲染子进程还在退出，给约 3 秒；Windows 上进程退出码出现后 `lockfile` 句柄还要几毫秒才关，立即重启会报「Lock file can not be created」并在 Playwright 里变 ECONNRESET，所以先按 `--user-data-dir` 记下整棵进程树（`app.process()` 是 `cmd.exe` 包装）。非 Windows 的 `SingletonLock` 是指向「主机名-pid」的符号链接，强杀后残留，新实例见 pid 已死就接管。`close` 失败时进程可能已自行退出，`taskkill` 报「not found」视为已退出。场景在 hold 与 release 之间抛错时门还关着，卡住的请求让运行一直进行、应用拒绝关闭，`quit` 要等满 10 秒才强杀，所以抛错时先放开门。
4. 退出码约定：前置不齐、没有启动应用记为 3，与失败 1、参数错误 2 分开，批跑时归「未跑」。
5. 失败现场取证（截图、DOM、无障碍树）本身失败不能盖掉原来的错误；启动失败时调用方拿不到 `page`，只能退出前就地取证。没有构建就启动，Electron 会在桌面弹出找不到应用的对话框，所以启动前先 `assertBuilt`。
6. `--lang` 固定 Chromium 的界面语言：隔离目录是新建的，应用没存过界面语言，会按 `navigator.language`，非中文宿主上会落到英文而场景按中文找控件。驱动的冷启动按中文书房判断就绪，所以涉及切语言的场景要先切回中文再重启，重启后再写回目标语言。
7. 会话里任何一步（含收尾清理）抛错都收成该会话的错误，不会逃出去，结果 JSON 与密钥扫描一定执行；`Node` 对未处理的拒绝会直接退出、诊断 JSON 写不出，所以旅程里 async 处理函数抛出、悬空的拒绝都要提前接住。

### 二、凭据与真实模型

1. 真实模型模式的凭据只发往硅基流动这一个端点：主进程 fetch 被包住，按 route 放行、改道或拒绝；真实模式不跟随重定向，遇到 3xx 记下目标源并拒绝，模型输入与凭据只发往确认过的端点。包住 fetch 的源码会被送进 Electron 主进程重建，函数体不能引用外部变量。
2. 报错与诊断里若带出密钥，打印与写盘之前就遮掉并判这次失败，运行中途被打断也不会把密钥留在产出目录；产出目录与留作取证的隔离目录都要扫描，读不了的文件算扫描不完整、判失败；先扫密钥再打印，stdout 与结果 JSON 报同一份发现。应用把模型档案（含明文 Key）写在数据目录的 `models.json`，会话收尾删除它。模型请求日志只记路径、状态与响应头耗时，不记请求内容。
3. 真实模型场景不评判回复的文风与质量，只断言作者看得到的软件状态与库里的数据；单次模型操作上限取 10 分钟（真实回复可能几十秒到几分钟）。嵌入失败时应用会静默降级为只按字词检索，所以要显式核对知识库里没有缺向量的块。

### 三、授权与文件对话框

1. 渲染进程只能携带选择器签发的授权标识。驱动只在主进程桩住 Electron 原生对话框（用后还原），让生产 chooser IPC 照常签发授权，不绕过授权服务，也不向渲染进程暴露路径；授权标识是短期能力，不写入收据。
2. 恢复目标在授权之后、恢复之前被占用，正是 no-clobber 必须拦住的竞争；授权把父目录固定为规范真实路径，恢复收据里的目标必须正是这条授权路径。

### 四、启动验收与旧数据

1. RD-10 起外观只读写 v3 键，旧键（v1、v2）只读不写；两个都去掉，下次启动就从更早的主题键迁移。旧版本把图片皮肤记在全局数据的 `skins/manifest.json`，新版本不再读它，迁移时原样带进新数据目录留给回退。
2. 切换后失效的旧来源不得重新获得写权限；先重定位 appData 再让 Electron 推导 userData，保留产品的默认档案名。
3. 旅程脚本是 `.mjs`，导入不了无扩展名导入的 `desktop-registry.ts`，所以从源码读常量；v0.2.5 早于 `AI_NOVEL_VELA_HOME`，会从 `os.homedir()` 推导 `.vela`，所以升级夹具要覆盖 `USERPROFILE`。独立夹具 oracle 显式列出评审过的值，防止生产计数器回归让升级验收夹具重复同一实现而通过；夹具逐字取自 v0.2.5 的 `database.ts`，新版本可追加迁移列但须保留全部旧列的原顺序。
4. 2026-10-05 起只有正常结束（`stop`）的正文能直接存成草稿，按长度截断的要先续写或精简。

### 五、等待与定位的经验（真实 Electron 里踩过的坑）

- **模态与 aria-hidden。** Radix 模态与提示框开着时，其余节点被设为 `aria-hidden`，按角色找不到顶栏、侧页、设置导航、作品菜单，要按类名或 `aria-label` 找；`body` 为 `pointer-events: none` 时 `elementFromPoint` 会跳过元素，命中测试要临时放开。
- **按需挂载。** 运行历史、「历史」页签、资料页都是点了才挂载或读完才显示，必须在切走前读、或先等列表或空状态出现；章节列表只在「正文」阶段展开。
- **只等「没有」会空过。** 「没有进行中的胶囊」会在胶囊还没挂出时空过，所以要先取挂上过的次数；固定等待换成「等产出 X 的那次读取返回、再等两帧让 React 提交」。
- **动画与节流。** 对话框淡入 220 ms、确认框有进场动画，截图前要等走完；屏外窗口被判遮挡时 rAF 被节流，另用 `MutationObserver` 记 DOM 就绪时刻；Playwright 轮询有量化误差。
- **可访问名称会粘连。** 版本菜单项名称把「草稿 v1」与字数连成「v1120」，要按第一段文字找；只认 `v` 号，使 v1 不会认成 v10。
- **视觉隐藏的控件。** 开关与勾选框是视觉隐藏的原生 checkbox，点它所在的 label；原生下拉的箭头画在内容区里。
- **保存状态。** 先等顶栏变「未保存」再等「已保存」，不脏时顶栏本就写「已保存」，只等它证明不了保存发生过；放行的回应要给渲染进程一点时间，误把后来的输入当成已保存时顶栏会在此期间翻转。
- **Electron 41 的 `Promise was collected`。** Windows 上直接 `app.evaluate` 取值偶发该错误，Playwright 报成执行上下文销毁；先取句柄再读值、读完释放就不会。
- **竞态用门稳定复现。** 主进程通道上的门（`holdChannel`）让「保存或读取还没返回时作者已离开」稳定发生；包装 `ipcMain` 处理函数每进程只装一次，重复包装会丢掉中间别的包装；计数窗口记在请求到达时，清零前发出清零后才答完的不算进新窗口。
- **会话。** 界面打开作品后会话租约换了新的，驱动读库要回书房、自己再打开一次拿会话，之后界面重载才认新会话；驱动打开作品会让界面会话失效，界面不先回书房就退不干净。
- **替身要说明触不到什么。** 例如硬链接探测的替身碰不到 LanceDB 的原生提交；改写连续性事实的替身在写稿前要换回原处理函数；真实的盘满、只读造不出时只换处理器看文案。

### 六、性能测量

1. 账本记次数而不只是毫秒：次数与机器快慢无关，章数翻倍时它涨不涨比毫秒更能说明问题；主进程阻塞用相邻两次定时器的最大间隔（不用 `monitorEventLoopDelay`，它 `reset()` 后丢掉第一个间隔，操作一开始就卡住的那段会读成 0），正对照要同步占住主进程使读数约等于占用时长，反向对照确认停顿发生在上一窗口时本窗口只读到空闲值。「假死」证明：渲染端每 20 ms 发一次轻量 IPC，记最长往返，再在主进程里直接调处理函数，看轻量 IPC 被挡多久。
2. 启动计时量的是同一配置目录里的第二次冷启动：首次启动要迁移旧配置、建库，与之后的启动不可比。像素对比容忍每通道 ±2 级抖动。主进程停顿预算 500 ms（作者不会觉得窗口卡住）；预览预算 250 ms 按 42 MB 的那份夹具定。
3. 复用已造好的书（112 章批量造书要十几分钟），计时、录 profile、新旧构建对比都从同一份数据出发；复制夹具打开一次再把库换回原样，使下次从书房打开时作者付的是真实的那次升级。

### 七、夹具与假模型

1. 主进程 fetch 改道到本机假 OpenAI 兼容服务，零真实模型调用；假模型每章回同一段正文，所以第 6 章开头会被判成重演而不落稿，这类场景只看发出的合同。写稿先发一份短细纲再发正文，夹具把细纲另计，`requests` 只数正文请求。
2. 登记的用户决定：作品打开后落在「最后一章在写的那章」（#394 §6，用户决定 B）：大纲没写完时，只有蓝图与正文都没有才落在架构；有蓝图或正文就落到当前写作位置，空草稿不算开始。
3. 场景把作者看到的值收进 `measured`、最后一次性断言，使对照构建上失败时能看到每一项各是什么；对照构建上某步可能走不通，原因同样记进 `measured`。
4. 假模型的可达范围：只放行假服务的端口，关掉它就能制造连不上；认不出原因的连接失败在本机触发不了，换掉处理器只为看这条说明的样子。
