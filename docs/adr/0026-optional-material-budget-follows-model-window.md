# 可选材料的额度由模型窗口决定

2026-11-08，#279。本 ADR 补充 ADR-0023，不改它的原文。

## 背景

ADR-0023 取消了发送前按自估 token 拒绝，提示词放不放得下由服务商判定。但写稿和审修仍传 `budgetChars: 8_000`，乘字节系数后得到可选材料的额度。这个数的来历：

- 8a7c1792 把它定为材料总容量。
- 5b5a25dc 降为可选材料额度，取值沿用 DeepSeek V4 Flash 甜点区的经验。
- 成熟项目的必需材料常常已经超过它，知识库片段、活跃线索、较早定稿的证据于是全部被裁，不管模型窗口有多大。

## 决定

1. **窗口只决定放多少可选材料，绝不用于拒绝或失败。** 必需材料一律放，单独超过窗口也照常发出，由服务商按 ADR-0023 判定。作者不填数，也不会见到新的报错。
2. **额度由主进程算。** 可用输入 = 窗口 − 预留输出 − 安全余量（512），下限 0。
   - 窗口按「手填 > 拉取 > 预设 > 默认」取，不明模型默认 32,768。
   - 预留输出取实际发送值，与 ADR-0023 决定 2 同一个三者最小（预设、作者设置、根账单次上限）。
3. **这里的窗口优先级不改执行证据。** `resolveModelExecutionCapabilityEvidence` 是预设压过手填。它的结果进模型收据，恢复时要深比较，还参与输出钳制，改了会让在途运行报 `GENERATION_MODEL_CHANGED`。所以额度单独按决定 2 的顺序取窗口。
4. **换算只有一处：UTF-8 字节 ÷ 3**（`MATERIAL_BYTES_PER_TOKEN`）。不再按写作语言区分系数。
5. **可选材料按相关度放到整条提示词估算到达额度。** 材料以外的部分（模板、作者指令、系统角色）都计入。材料块的分隔符和覆盖缺口说明按每个来源 40 字节预留。首稿的短细纲是后追加的生成内容，按它的目标字数（500）预留。修稿把历史同时填进两个占位符，每条历史按两份计入额度。
6. **知识库片段之间保留快照排名。** 字面命中只决定片段和其他材料怎么穿插，片段彼此的先后归排名，额度不够时先裁排名靠后的。升级前冻结的快照没有排名，仍按字面命中。
7. **额度冻结进 `materialDecision` 收据。** 恢复同一次生成用冻结值，不按当前模型重算，否则提示词哈希和选中的定稿会对不上。审修在选材前才开运行，这时还没有收据，按运行里冻结的模型现算，选材后写进收据。

## 兼容

- 没有 `budget` 字段的旧收据不升版本。恢复时按收据记下的可选内容原样重现，也不按排名重排，代码里不留 8K 常量，收据也不会多出额度字段。
- 便携导出会清空 `materialDecision`（#634），恢复出的副本按没有收据读取，不影响审稿目标。

## 后果

- 默认窗口配很大的 `maxTokens` 时，可用输入可能压到 0，可选材料全不放。这是额度公式的直接结果，不另做兜底。作者填对窗口或调小输出上限即可，自动拉取窗口由后续 PR 处理。
- 字节 ÷ 3 对英文偏保守，英文项目放得比窗口实际能放的少。换算准确性让位于只有一处系数。
- 8 MiB 收据上限不变，各来源自身的条数上限也不在这次范围内。
