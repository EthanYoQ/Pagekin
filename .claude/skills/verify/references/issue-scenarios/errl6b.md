## 新建、删除作品失败和空库时说真正的原因（#702，err-l6b）

场景在 `scripts/redesign/errl6b-scenarios.mjs`。每类中英各一个（`-zh`、`-en`），`-en` 的场景先切到英文界面。权限用 `icacls` 拒绝当前用户（SID 取自系统的 `whoami.exe`），收尾还原。修复前：新建弹「创建项目失败」，正文是「发生错误：」加带路径的 `EPERM` 原文；删除弹「删除失败，项目已停用」，正文是 `EBUSY` 原文接「回滚失败：」和 `ENOENT` 原文；0 字节库弹「无法识别项目格式…核查创建该项目的软件和版本」；库文件不在弹带路径的 `ENOENT` 原文。

| 名称 | 检查 | 截图停在 | 夹具模型 | 对应 |
|---|---|---|---|---|
| `errl6b-create-denied-*` | 只在 Windows 上跑。选的保存位置拒绝建文件夹（`(AD,WD)`）：弹「新建作品失败」，正文「没有权限在所选位置新建作品。请换一个保存位置。」 | 新建对话框上的失败提示 | 否 | #702 |
| `errl6b-delete-ok-zh` | 带知识库（`kb:import-planning-text`）的书正常删除：弹「项目「灯塔」已删除」，文件夹没了，`measured.waitedSeconds` 记点删除到提示出现的秒数 | 删除后的书房 | 否 | #702 |
| `errl6b-delete-busy-*` | 只在 Windows 上跑。作品文件夹里的 `人物小传.docx` 被 PowerShell 独占打开：10 秒内弹「删除作品失败」（修复前约 67 秒），`measured.waitedSeconds` 记等待秒数，正文先说文件夹没删完、有文件被别的程序占用，再按库文件还在不在接「作品还开着…再删除一次」或「《灯塔》已关闭…「从最近项目移除…」」 | 书房上的失败提示 | 是 | #702 |
| `errl6b-delete-denied-*` | 只在 Windows 上跑。作品里的 `资料` 子文件夹拒绝删除（`(OI)(CI)(D,DC)`）：正文先说没有删除其中文件的权限、检查文件夹权限，后半句同上。整个作品文件夹都拒绝删除时，打开着的作品读不了目录，删除在会话校验处被拒，不是本场景 | 书房上的失败提示 | 是 | #702 |
| `errl6b-delete-unknown-*` | 在主进程里把 `fs/promises` 的 `rm` 换成直接报 `EIO`（实机造不出没归类的删除失败），收尾换回：正文只说「作品文件夹没删完。」，不说被别的程序占用或没有权限，后半句接「作品还开着…再删除一次」。不限 Windows | 书房上的失败提示 | 是 | #702 |
| `errl6b-empty-zero-*`、`errl6b-empty-missing-*` | 冷启动前把 `project.db` 截成 0 字节或删掉，从书房打开：弹「打开作品失败」，正文「作品文件里没有内容，打不开。导出过存档的，可以在设置的「项目备份」里点「从本地存档恢复副本」。」 | 书房上的失败提示 | 是 | #702 |
