## 上下文容量交给服务商（#77 讨论，ADR-0023）

场景在 `scripts/redesign/d77-scenarios.mjs`。两个场景都把模型档案设成作者填的 64K 上下文。`fake.rejectContextLength()` 让假模型对之后的每个对话请求回 HTTP 400，错误体取自 `electron/llm/__tests__/provider-context-length-samples.json` 里的 DeepSeek 样本，和单元测试用同一份；传 `false` 恢复正常回复。

| 名称 | 检查 | 截图停在 | 夹具模型 | 对应 |
|---|---|---|---|---|
| `d77-capacity` | 写第 3 章，正文提示词的字节数超过作者填的上下文窗口。请求不在发出前被拒绝：短细纲与正文各发一次，正文落到编辑器里（`measured.promptBytes`、`measured.chats`） | 第 3 章正文 | 是 | #77 |
| `d77-context-length` | 写第 3 章，假模型以上下文超长拒绝第一个请求，之后不自动重发（`measured.chats` 只有一次 `context-length`）。运行卡片显示登记的说明（作品内容没有变动、换用上下文更长的模型、调低最大输出 Tokens、再重新生成）和「本次未保存草稿或正文章节。」；不出现「上下文窗口」「请调整章节要求」和服务商原文（`measured.card`） | 失败的运行卡片 | 是 | #77 |
| `ctx-lease-learned-window` | 拉取到 1M 窗口、输出上限 65,536，假模型第一次以硅基流动样本（真实窗口 32,768）拒绝。学到的窗口写进模型档案（`measured.learnedWindow`），拉取的数不变（`measured.storedWindow`），之后每个请求的 max_tokens 都是 16,384（`measured.maxTokens`），没有失败卡片；设置页窗口来源显示「实测」，不提示作者调整（`measured.conflictPrompts` 为 0） | 写完的章节、设置页窗口来源 | 是 | #279 |
